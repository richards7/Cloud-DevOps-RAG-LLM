A chatbot that answers from your documents, not its training data — and doesn't go down when one API does.

Retrieval-augmented generation over a cloud & DevOps knowledge base, with automatic fallback across multiple LLM providers. Built to show its work: every answer names its sources and which model produced it.

How a question becomes an answer

1

Retrieve

The query is embedded and matched against a local Chroma vector store built from the markdown files in the knowledge base.

2

Ground the prompt

The retrieved chunks are inserted into the prompt as context, so the model answers from what's actually in the docs.

3

Route to a provider

Gemini is tried first; if it fails or times out, the router falls back to OpenAI automatically — no dropped request.

4

Log and return

The query, sources, provider, and latency are logged to a database, separate from the knowledge base itself.

How it's built

Provider-agnostic by design

An abstract LLM interface means adding a third provider is a new file, not a rewrite.

abstractionrouter.py

Local embeddings

Retrieval doesn't depend on an external embedding API — one less thing that can fail.

chromadb

Cloud-native deploy

Containerized with Docker, deployed to Cloud Run — stateless, scales to zero.

dockercloud run

Operational visibility

Every chat is logged with its provider and latency — the start of real observability.
